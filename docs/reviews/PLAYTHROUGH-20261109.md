# 실제 학생 전체 플레이 검증 — 2026-11-09

이 문서는 실제 학생의 기능 진행(B), 화면(C), 브라우저 오류(E), 진행 저장(F)을 검증한다. 전체 교육 품질·성능·보안·배포 판정은 범위에 포함하지 않는다.

## 검증 방법

1280×800의 빈 전용 Chrome 프로필에서 일반 학생 모드로 시작했다. 시작 화면과 지도부터 모든 관찰, 정답 선택, 연주, 배치, 슬라이더 조절, 다음 활동을 실제 DOM 마우스·키보드로 수행했다. 자동재생 2배도 화면의 속도 선택과 재생 버튼으로 설정했다. 학생 기록의 localStorage는 검증 목적으로 읽기만 했다. route·work·증거·정답을 저장소에 심거나 앱의 판정 함수를 직접 호출하지 않았다.

10종 의뢰의 라운드는 부위 4, 리듬 3, 신호 4, 상자 정렬 2, 멜로디 3, 크기·높낮이 주문 4, 감지기 3, 전달 사례 6, 해결 도구 4, 축제 1로 총 34개다. 활동 완료 후 시설별 16초 영상 5편을 실제 재생 종료까지 확인하고 최종 5문항과 정식 인증서로 진행한다.

## 중간 실행과 발견 사항

`final-student-v2`는 새 학생으로 20활동·34라운드·영상 5편·최종 5문항·정식 인증서를 모두 실제 완료했다. 인증서를 새로고침한 뒤에도 증거 20개, 정답 5개, 완료 날짜와 정식 인증서가 유지됐다. 이 실행은 다음 화면 문제를 발견했으므로 최종 화면 통과로 분류하지 않는다.

포인터 문제는 실제 이벤트를 document capture 단계와 다음 프레임에 읽기 전용으로 추적했다. A 버튼은 pointerdown 때 (486.47, 238.20), 319.52×44였고 자동 상태가 waiting→idle로 바뀐 직후 (24, 362.83), 387×48로 이동했다. 같은 좌표의 pointerup은 텍스트, click은 action이 없는 DIV에 도착했고 저장된 답은 바뀌지 않았다. 실험대 높이 343.03→345.41px 변화가 컨테이너 레이아웃 전환을 일으킨 상태였다.

별도 교사용 경계 재현은 화면의 설정·교사용 전환과 화살표 키로만 이동했다. 실제 학생 완주 프로필과 구분했다. 첫 수동 제스처는 미리보기를 정지하고 원래 설정만 복원하며, 다음 명시 조작부터 판정하는 수정은 `boundaries-v3`에서 12항목·10상태·오류 0으로 재검했다.

수정 후 실제 획득 기록으로 노트의 재방문 버튼을 눌러 집중 재검했다. `font-existing-fixed`의 자 길이 18·12·6과 mix 시연 전 구간은 1280×800에서 최소 16px, 1920×1080에서 최소 18px, scale 1.000으로 24상태 오류 0이다. `trace-pointer-fixed`에서는 첫 pointerdown/up/click이 모두 choice0을 유지하고 저장된 답도 1→0으로 반영됐다. 두 실행 모두 시작·종료 소스 해시가 같다.

별도 빈 프로필의 `map-early-fixed`는 지도 배경 요청만 4.5초 지연했다. 로딩 안내 중 추천 버튼을 한 번 누른 뒤 추가 클릭 없이 준비 완료 후 lesson0로 실제 입장했다. 고정 800ms만 기다리던 앞선 probe의 지도 timeout은 로딩 준비를 기다리지 않은 경계였고, 정규 플레이는 실제 `.map-load-state` 안내 종료를 확인한 뒤 누른다. 제품은 준비 중 조기 클릭도 기억하도록 보완했다. 이 항목을 확정된 정상 플레이 차단으로 분류하지 않는다.

리듬은 수동 울림 하나 입력→실제 새로고침→자동재생 종료 뒤에도 ‘처음부터’ 안내와 clear 강조가 유지됐다. 기존 부분 입력을 지운 다음 정상 3라운드를 모두 재연주하고 시설 복구로 진행했다. 소리가 멈춘 상태를 다시 울림 입력으로 안내하지 않도록 복원 상태와 자동 관찰의 마지막 안내를 함께 수정한 회귀를 확인했다.

`final-student`의 초기 중단은 제품 진행 오류가 아니었다. 소리굽쇠를 자동으로 멈춘 뒤 650ms 관찰 중에는 nextSelector가 잠시 비활성 버튼을 가리켜 보이는 강조가 0개였다. 자동 상태가 playing일 때의 이 0개만 이유를 기록해 허용하며, 대기·완료·정지 상태의 다음 타깃과 모든 겹침·잘림·가림 검사는 유지한다.

## 최종 재검 기준

수정 후 빈 학생 프로필로 전체 경로를 다시 수행했다. 1280px 이상 화면은 실제 렌더 글씨 16px, 800~1279px 화면은 14px보다 작으면 실패한다. 스크롤, 화면 밖 필수 조작, 숨겨진 필수 조작, 44px 미만 조작 영역, 글자 잘림, 아이콘 겹침, 버튼 가림, 12자 이상 반복 문장도 실패다.

`final-student-v3`는 1280×800의 빈 프로필부터 정식 인증서 새로고침까지 303상태, 실제 획득한 기록으로 915×412·1024×768·1920×1080·830×515의 5시설 대표 활동을 각각 재방문한 상태까지 총 485상태를 수행했다. 기능·화면 가림·진행 오류와 JavaScript·HTTP 오류는 0건, 수리·재시도는 0회다. 각 추가 뷰포트는 0·5·8·12·17 활동에서 자동관찰→오답→정답→다음 이동을 확인했다. 915·830에서는 미리보기 인계 안내와 진단 오답/수정도 확인했다. 이 4개 뷰포트는 빈 상태부터의 전체 34라운드 반복으로 표현하지 않는다.

v3의 인증서 발급 직후 보존한 획득 기록에는 proof 합계 34, 증거 20, 최종 답 5, restored=true, 실제 완료 날짜가 있다. 자 관찰 도중 새로고침 후 관찰 기록·route 복원과 자동재생 정지, 리듬의 중단 복원 및 재연주, 인증서 새로고침 후 날짜·정답·증거 유지도 확인했다.

v3 후반 830의 전달 카드와 진단 화면에 12.7px·9.9px가 남아 가독성 기준을 넓혔다. 이후 제품 변경은 `src/workbench.css` 한 파일의 짧은 실험대 배치 적용 범위뿐이었다. 짧은 실험대 규칙을 확장한 뒤 360 완료4에서 발견한 라벨 침범은 해당 규칙을 가로 방향에 적용해 수정했다. 360 세로는 전용 세로 배치를 유지한다.

최신 `final-css-student-v2`는 v3가 실제 획득한 동일 프로필을 사용했다. 360×740 완료4에 노트로 재방문해 세기를 실제 Home키로 ‘약하게’로 바꾸고, 830의 5시설 자동관찰·오답·정답·다음 이동과 진단 오답·완료, 미리보기 인계를 다시 수행했다. **48상태에서 최소 14px·scale 1.000, 오류 0**을 확인했다. 사진에서도 라벨과 A/B 카드가 분리된 것을 직접 확인했다. 1280 이상의 기능 완주와 이 CSS 후속 검증의 소스 해시는 각각 보존하며, 각 실행의 시작·종료 해시는 동일하다. 두 실행 사이의 해시 차이는 workbench.css뿐이다.

최종 학생 실행과 별도로 기존 8개 뷰포트×20활동 및 긴 의뢰·완료·오답·재생·교사용 상태 282개에 830×515의 기본 20활동과 완료 20활동을 추가했다. 360·390 세로의 완료 상태도 각각 전체 20개를 검사하도록 28개를 더해 총 350상태 자동 전수를 수행했다. 이 전수 검사만 저장소 fixture를 사용하며 실제 학생 완주와 증거를 분리한다.

별도로 진행된 NPC quiet 변경은 유지했다. v2 종료 때 app·audio·npc-guide의 파일 해시가 시작과 달랐으며 실행 원본과 시작·종료 해시를 보존했다. 따라서 v2는 소스가 동결된 최종 판정 자료로 사용하지 않는다.

실제 탭 hidden은 미검증이다. 전용 headful Chrome의 탭 전환·창 최소화·focus emulation 해제로도 이 환경에서는 visibilityState가 visible로 유지됐다. 합성 visibility 이벤트로 실제 숨김을 통과했다고 주장하지 않는다. 물리 태블릿·Safari·실제 스피커 청음도 미실측이다. 브라우저는 출력 음소거 상태로 동작과 재생 종료를 확인했다.

재현 명령은 다음과 같다. 실제 학생 명령의 실행 이름은 빈 프로필에 사용할 새 이름이어야 한다. CSS 후속은 실제 완주로 획득한 프로필에 `QA_PROFILE`을 지정해 `--resume --small-existing`으로 실행한다. 전수 런타임 사본은 이번 증거 폴더 안에 보존했다.

```sh
node scripts/qa-full-play.mjs final-new-student
```
