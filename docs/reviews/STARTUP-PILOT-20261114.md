# 울림도시 대작전 — 첫 화면과 지도 장애 복구

2026-11-14 · 11번 · 로컬 수정 및 검증. 운영 주소는 https://sound-discovery-lab.yelsam.workers.dev/ 이며 배포하지 않았다.

기존 제목 화면과 ‘도시 이야기 보기’ 대화·음성을 유지했다. 시작 화면의 스타일 요청 10개는 순서를 유지해 1개로 묶었다. 지도 렌더러와 이동 조작은 지도 진입에서, 실험 화면과 자동재생은 첫 실험 진입에서, 도전 화면과 조작은 해당 도전 진입에서 가져온다. 이전 저장 기록을 읽는 데 필요한 판정 규칙은 작은 모듈로 분리했다.

| 측정 구간 | 일반 로컬 전 → 후 | 10Mbps·40ms·CPU 4배 감속 전 → 후 |
|---|---:|---:|
| 첫 콘텐츠 표시 | 48 → 24ms | 632 → 348ms |
| 시작 버튼을 누를 수 있을 때까지 | 24 → 25ms | 584 → 546ms |
| 도시 이야기 → ‘탐험하러 가기’ 버튼 | 32 → 32ms | 45 → 47ms |
| 이야기에서 지도 이동 준비까지 | 175 → 179ms | 4.84 → 4.79초 |
| 지도에서 첫 시설 선택 → 고무줄 악기 버튼 | 14 → 31ms | 24 → 92ms |
| 시작 버튼 전 JS | 23 → 15개, 약 250 → 149KB | 동일 |

Chrome 1280×800, 같은 로컬 서버의 두 빌드를 교대로 각 5회 실행한 중앙값. 매번 새 브라우저 컨텍스트, HTTP 캐시·서비스워커 차단, 모션 줄이기 설정. 준비 시간은 해당 화면의 버튼 중앙이 가려지지 않아 클릭할 수 있게 된 시점 기준이다. 지도는 그림과 이동 조작이 준비될 때까지 잰 값이다. 제한망에서 첫 콘텐츠 표시는 빨라졌고 시작 버튼 개선 폭은 그보다 작았다. 첫 실험 코드 로딩이 진입 시점에 추가됐다. 학교 실기기나 운영 서버의 전후 수치는 아니다.

- 지도 코드를 차단하고 도시 이야기를 열었다. ‘첫 소리 실험 시작’을 눌러 고무줄 악기와 소리굽쇠를 울리고, 공통점에 답해 실제 증거를 저장했다. 새로고침 뒤에도 기록이 남았다.
- 지도 코드 및 지도 그림을 각각 차단했다가 해제해 ‘지도 다시 열기’로 복구했다. 실험 코드를 차단했다가 해제한 경우에도 같은 활동을 다시 열었다.
- 학생 경로에서 첫 두 실험을 마친 뒤 도전으로 이동해 도전 코드 요청과 첫 조작을 확인했다. 그 이전에는 도전 코드를 요청하지 않았다.
- 서비스워커를 켠 상태에서도 타이틀에서 지도·실험·도전 코드 요청이 없었고, 온라인에서 한 번 연 실험은 연결을 끊고 새로고침해도 열렸다.
- 소스 구문 검사와 단위 테스트 126개 통과. Chrome 터치 에뮬레이션에서 지도 복구를 확인했다. 실제 iPad·Android 기기와 전체 학생 경로 완주는 이번 작업에서 확인하지 않았다.
