# 울림도시 대작전 — TRD

갱신일: 2026-10-22. Node 20+ 내장 HTTP 서버·빌드, 브라우저 ES modules·DOM·CSS·Canvas 2D·Web Audio를 사용한다. 외부 패키지·CDN·폰트 설치가 없다. D: exFAT에서 일반 파일 읽기·쓰기·복사만 수행하고 개발 프로세스의 TEMP/TMP는 D:\DevTemp를 쓴다.

## 저장·접근·완료

기존 저장 키 ullim-city-v1을 유지하며 내부 데이터 버전은 2다.

```text
{ version:2, work:{0..19}, evidence:{0..19},
  settings:{muted,admin,bgm,sfx,bgmVolume:0..100},
  lastRoute, finalAnswers, restored, completedAt, previousCompletion }
```

v1 읽기 시 원본을 ullim-city-v1-backup-v1에 한 번 백업하고 구 work·evidence·lesson 경로를 새 위치로 옮긴다. 구 완료 날짜는 previousCompletion으로 보존하며 20개 활동의 새 인증서를 자동 발급하지 않는다. 저장 데이터는 허용 필드·범위만 정규화한다. JSON으로 빈칸이 null이 되는 정렬 배열은 슬롯 위치가 이동하지 않도록 다룬다. 실행 중인 소리 상태는 리로드 후 다시 실행하지 않는다.

페이지는 home, map, lesson/0..19, final, result다. 첫 활동은 열리며 다음 활동은 직전 증거 또는 해당 활동의 기존 증거가 있어야 접근한다. 관리자 불리언은 접근 조건만 우회한다. 시설 복구는 네 증거 모두, 최종 복구는 증거 20개·최종 정답 5개·완료 날짜를 요구한다. 관리자 해금만으로 증거·보상·정식 인증서가 생기지 않는다.

조작은 work에 저장하고, 증거 제출 시 공통 판정이 통과한 관찰 자료를 복사한다. 재실험 중 기존 증거는 보존하며 성공 제출할 때 갱신한다. 크기 비교는 A/B 쌍의 스냅샷을 보존한다. A/B를 새로 만들면 비교 work를 다시 청음하게 초기화하되 기존 성공 증거는 유지한다. 저장 읽기·쓰기 실패는 현재 세션 플레이를 유지하고 저장 상태를 알린다. 초기화는 확인 후 이 앱의 기록만 지우고 소리 설정을 유지한다.

## 추가 활동과 근거

추가 활동은 parts, rhythm, signal, sort, melody, mix, sensor, classify, solutions, festival이다. 각각 4·3·4·2·3·4·3·6·4·1 소과제를 갖는다. 공통 challenge.proof의 순서와 예상 결과가 모두 일치해야 증거를 낼 수 있다. 라운드 완료 후 임시 조작 필드는 비우고 proof를 남긴다. 재도전은 해당 work만 초기화하며 이미 모은 증거를 자동 삭제하지 않는다.

## 오디오

사용자 클릭 후 AudioContext를 생성·resume한다. 실험음·효과음은 sfx 설정, 배경 음악은 bgm과 별도 gain을 사용한다. 저장된 bgmVolume 0~100을 configure에 전달할 때 100으로 나눈다. 상단 음소거는 둘 모두 정지한다. 배경 음악은 home, map, result에서만 재생하고 활동·마지막 문제 청음에는 섞지 않는다.

재생 교체·화면 이동·탭 숨김 시 발음 노드와 예약을 정리한다. generation 번호로 늦게 끝나는 비동기 준비가 낡은 소리를 다시 시작하지 않게 한다. 탭 숨김 후 자동 재생하지 않고 새 제스처를 기다린다. 같은 북의 크기는 같은 주파수의 진폭, 같은 자의 높낮이는 주파수로 표현한다. 소리굽쇠 멈추기는 즉시 재생을 종료한다. 합성 파형은 실제 계측·물질별 속도·음량 비교값이 아니다.

## 지도·이미지·UI

지도 좌표계는 생성 그림과 같은 1672×941다. map-world.js가 문·길 노드·연결·빛 좌표를 정규화해 같은 좌표계로 유지한다. 최단 경로와 길 위 이동으로 건물·숲을 관통하지 않게 한다. 마지막 위치를 현재 세션에서 기억하고 카메라가 탐험가를 따라간다. 방향키/WASD·화면 방향 버튼·길/목적지 선택을 지원한다. 울림새는 이동 궤적을 뒤따른다.

DOM 구조는 .map-viewport > .map-world > canvas#world와 같은 world 안의 목적지·동행 버튼이다. 접근 가능한 DOM 버튼을 그림 위에 놓고 canvas는 이동과 시각 피드백을 맡는다. 보행은 4열×4행 RGBA 시트에서 투명 여백을 계산해 발 기준점을 맞춘다. 화면 이탈·모달·탭 숨김 때 입력과 RAF·리스너를 정리하고 이미지 실패·재시도 상태를 제공한다. 모션 감소 환경에서는 이동 애니메이션을 줄인다.

실내는 DOM 버튼·range·선택 상태와 2D 이미지로 구현한다. props 경로 표가 소품 이미지 교체 지점이다. 추후 3D는 이 표시 계층에 별도로 도입하며 과학 판정·저장 데이터와 분리한다. 이번 빌드는 실제 GLB·3D 엔진을 요구하지 않는다.

## 빌드·검증

assets에 기존 이미지 11개와 생성 이미지 13개, 총 24개를 명시한다. 현재 원본 합계는 42,823,417 bytes이며 실행에 쓰지 않는 참고 이미지·생성 manifest는 빌드 복사 대상이 아니다. 이 값은 압축·최적화 전 원본 크기이며 네트워크 성능 보장이 아니다. 기존 dist는 파일을 덮어쓰는 방식이며 원본을 삭제하지 않는다.

npm run check, npm test, npm run build로 구문·순수 로직·에셋 존재를 검사한다. 브라우저에서는 20활동 정상 경로·오답·증거·구버전/리로드·설정·지도·마지막 결과를 검사한다. 1280×800과 1024×768을 우선하고 1920×1080·모바일 보조 화면을 확인한다. 실제 수행한 결과만 최종 보고서에 남긴다. 기기 스피커 실청·물리 태블릿 터치·인쇄 장치·학교 네트워크 동시 접속은 별도 현장 확인 대상이다.
